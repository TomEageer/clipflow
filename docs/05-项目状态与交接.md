## 4. 不可违反的硬规则（都有实测支撑，改之前先看数据）

| 规则 | 依据 | 守卫 |
|---|---|---|
| **禁止 `ORDER BY rank`** | 2 万条命中 46ms vs `rowid DESC` 0.30ms，快 150 倍；且剪贴板用户要"最近"不要"最相关" | 有测试扫源码 |
| FTS5 必须 `detail=full` | 只有它支持短语查询；中文 bigram 检索退化成 AND 匹配精度就崩 | — |
| 中文走**应用层 bigram 分词** | FTS5 自带分词器把连续汉字当一个词元，搜「订单」匹配不到「订单支付回调」 | 有测试 |
| **ClipflowCore 禁 import AppKit/SwiftUI/UIKit/VisionKit** | 呈现层可整层替换的前提 | 有测试扫源码 |
| 列表排序用 `usedSeq` 不用时间戳 | 同一毫秒内多次写入时间戳完全相同，排序变未定义（实测挂过测试） | 有测试 |
| 压缩阈值 512B | 120B 文本压完仍 97.5%，纯白费 CPU | 有测试 |
| 库文件 600 / 目录 700 | 竞品 Paste 是 644，同机任意用户可读 | 有测试 |
| 读剪贴板**必须与检测同步**，不能异步延后 | 内容是瞬态的；延后读会张冠李戴。实测 7 次复制，异步读把后 5 次全读成最后一条 | — |
| 多文件必须保留 itemIndex | 拍平后写回时同一 UTI 反复 setData，三个文件只剩一个 | 有测试 |
| 变换不改库里的原始内容 | 保真是地基 | — |

## 5. 踩过的坑（**这一节最值钱**，全部有实测）

### 5.1 我自己的测试方法错了三次 —— 同一个根因

**跨进程行为的测试，对端必须模拟真实进程形态。**用短命/无 run loop 的进程当写入方，测出来的是脚手架的病，不是被测对象的病。

| 现象 | 我的错误结论 | 真相 |
|---|---|---|
| 读 `public.utf16-external-plain-text` 阻塞 18~28 秒 | "macOS 广告了兑现不了的类型"，据此加黑名单 | **写入进程没跑 run loop**。它是 lazy promise，靠拥有者的 run loop 兑现。真实 App 都跑 run loop，**根本没这问题**。黑名单还造成了保真度倒退，已回退 |
| 多 item 剪贴板写回只剩 1 个 | "多文件功能坏了" | **写入进程写完就退出**，多 item 内容会塌成 1 个。App 是常驻的，不受影响 |
| 「重新复制置顶」验证失败 | "排序没生效" | **CLI 是旧二进制**（build-app.sh 当时只编 App 产物）。数据库里其实是对的 |

> 用户当时的质疑一针见血：「别人都可以为什么你不可以？如果别人没问题，就代表这是你的问题」。
> 这句话应该成为默认的排查起点。

### 5.2 「代码写了但从没被执行过」

| 坑 | 表现 | 根因 |
|---|---|---|
| Esc 关不掉面板 | 按了没反应 | `NSTextField` 获得焦点时真正的 first responder 是 **field editor**，`keyDown` override 收不到。必须用 `control(_:textView:doCommandBy:)` |
| watch 命令静默什么都不做 | 头部打印了，之后无输出 | `main.swift` 顶层是 `@MainActor`，普通 `Task {}` 继承 MainActor 隔离，而主线程阻塞在 `sem.wait()` |
| CLI ocr 命令挂死十分钟 | 无输出 | 同上：`ImageAnalyzer` 是 `@MainActor`，主线程被 `sem.wait()` 阻塞就永远跑不起来。**必须泵 run loop** |
| Ctrl+C 停不下来 | 信号处理器不执行 | 信号源挂在 `.main` queue，而主线程被阻塞 |
| 后台日志全丢 | 重定向到文件后没内容 | stdout 默认全缓冲，长驻进程要 `setvbuf(_IOLBF)` |

### 5.3 权限与签名

**ad-hoc 签名的「指定要求」绑二进制哈希，每次重编都作废辅助功能授权**，而系统设置里那条记录还在、还打着勾——看着像已授权，实际不生效。开发期反复重编时极其隐蔽。
→ `build-app.sh` 改用 Apple Development 证书，指定要求绑证书 + bundle id，重编不影响。

**录制快捷键时会误触发面板**：Carbon `RegisterEventHotKey` 在系统层就把按键吃掉，App 内 local monitor 收不到。录制期间必须先注销全局热键，并在取消/关窗/切走时兜底恢复。

### 5.4 UI

- 鼠标划过即选中 + 选中即滚动 = **反馈循环**，列表追着鼠标跑。只有键盘驱动才允许滚动
- 数字输入框（`TextField` + `.number`）要按回车才提交，用户改完看着变了其实没保存 → 「设置不了存储上限」
- 滑块刻度对不上：数值列占了宽度导致刻度行与滑块轨道宽度不同；且"中间档"按索引取只在特定档位数下才落在中点 → 改用 `NSSlider` 原生 tick marks
- 状态栏图标默认 SF Symbol 渲染是 16×18，系统图标高度普遍 11~14，**显得又大又挤** → 固定 18×18 模板图 + `squareLength`
- 面板到屏幕边缘只做位置钳制而不镜像内容，"跟随鼠标少动"的目的就落空了
- 列表上下反转（曾试过）**违反阅读直觉**，已撤销；只保留左右镜像
- **两栏写死宽度 = 窗口白拉**：`listColumn.frame(width: 380)` + 预览固定宽，
  窗口拉多大内容都不动。宽度必须由**比例**算（`SplitLayout`），且存比例不存像素 ——
  存像素的话拉宽窗口时增量全压给预览，列表永远保持原样
- **`isMovableByWindowBackground` 会吃掉 SwiftUI 的 `DragGesture`**：面板没有标题栏，
  拖背景是唯一能挪窗口的方式，但窗口背景拖拽在 AppKit 层就截走了鼠标事件，
  **排在 SwiftUI 手势之前**。实测拖分隔条时整个面板跟着跑了 135pt，比例一点没变。
  `mouseDownCanMoveWindow = false` 是唯一的退出开关，**SwiftUI 没有对应修饰符**，
  这类"要在可拖背景的窗口里放自己的拖拽区"的场景必须落到 NSView（见 `SplitterHandle`）
- 1pt 的拖拽热区**抓不住**，鼠标从旁边滑过去；命中区要宽出去（7pt）。
  另外画在上面的视觉细线默认参与命中测试，会把正中央按下的拖拽吞掉
- **贴边时优先缩尺寸，不要翻到另一边**：面板能被拉到 1000pt 以上，
  "右边放不下就开到左边"会让鼠标一进屏幕右半区就触发镜像，而镜像会把列表和预览**左右对调**，
  每次唤出布局都不一样，比面板窄一点难受得多。见 `PanelPlacement`（有测试盯边界）。
  实测（主屏 1800pt、偏好 740×620）：鼠标 x=1100/1250 缩成 692/542 且不镜像；
  x=1400 起右侧只剩 392pt，低于下限才翻到左边并恢复完整宽度
- **自适应缩小绝不能回存尺寸**：`onResize` 会把 `setFrame` 的结果写进设置，
  而贴边缩小是"这一次显示"的决定 —— 存下来的话面板一次比一次小，
  用户拉过的尺寸就这么悄悄丢了。程序化摆放期间必须挂 `isPlacing` 闸门
- **就地编辑的输入框必须有"点别处即退出"这条出路，而且不能只靠 `controlTextDidEndEditing`。**
  点击 SwiftUI 视图**不会**让 NSTextField 交出 first responder —— SwiftUI 的按钮、胶囊
  根本不进 responder chain，输入框始终保持聚焦，结束编辑的回调永远等不到。
  实测表现：分组胶囊双击进改名后点别处，输入框一直挂在那儿下不来。
  解法见 `InlineTextField`：自己装 local mouseDown 监听，落在输入框以外就提交并退出，
  事件原样放行（那一下点击该选中谁还是选中谁）
- **自绘菜单必须有悬停高亮**。系统菜单一直有这个反馈，自绘的不给就显得整块是死的，
  用户甚至不确定这几行能不能点。见 `MenuRow`
- **`onTapGesture(count: 2)` 会让单击变慢约 370ms。** 只要挂了双击手势，
  单击就必须等双击超时才能确认（系统那一档，默认 0.5s）。
  实测：点分类胶囊到画面变化 370ms，而 App 内部处理只用 2~5ms —— 差额全是这段等待。
  正确做法是照 AppKit 的语义自己判：单击立即生效，第二下落在
  `NSEvent.doubleClickInterval` 内再补一个动作。
  （试过用 NSView 覆盖层读 `clickCount`：盖在上面会吞鼠标、玻璃的 `.interactive()`
  收不到 hover；放 background 又完全收不到点击。都不行。）
- **Liquid Glass 试过又拿掉了，别再加回来。** 三条理由：
  ① 每个胶囊一层实时背景模糊，实测每次切换多 15~68ms 渲染，本来 2~5ms 就够；
  ② `GlassEffectContainer(spacing:)` 是"相距多近的玻璃要融合"、不是内边距 ——
  给 6 而胶囊间距只有 4，选中色直接流到左右两个胶囊上，很难看；
  ③ 它是 macOS 26+ 才有的，为它整条要拆两套 `#available` 分支。
  普通胶囊一套代码通吃 macOS 14 到最新，还更快。
  （顺带：**新系统专属 API 必须走 `if #available`**，直接调会让老系统用户连 App 都起不来。）
- **`NSHostingView` 默认允许窗口背景拖拽，会吃掉 SwiftUI 里的所有拖拽。**
  面板没标题栏、靠 `isMovableByWindowBackground` 拖背景挪窗口，而 AppKit 是问
  **鼠标下那个 NSView** 要不要接管的 —— SwiftUI 的内容全画在 NSHostingView 一个视图的
  图层里，于是不管按在哪儿（包括挂了 `.draggable` 的胶囊上）都被当成"拖窗口"。
  实测：拖分组胶囊排序，整个面板跟着鼠标跑、胶囊纹丝不动。
  解法见 `PanelHostingView`（统一关掉）+ `WindowDragHandle`（把拖窗口的能力
  显式还给搜索栏那一行）。⚠️ 只关不还的话面板就彻底挪不动了
- **可能溢出的一排必须套滚动容器。** 分类条第一排原来是裸 HStack，标签一勾多就溢出 ——
  里面的胶囊都是 `fixedSize` 压不动，于是整排被居中裁掉**两头**，左边的「全部」直接不见。
  见 `ChipScrollRow`（两排共用）
- **别为了"箭头该不该置灰"去测宽度。** 判断装不装得下要在滚动内容和容器上各挂一个
  GeometryReader + preference，这两处测量会持续喂 SwiftUI 的布局循环 ——
  实测两排各两个测量之后，面板打开时主线程 CPU 从 ~20% 涨到 **38.8%**，去掉就回落。
  装得下时按箭头只是 scrollTo 一个已在视野里的元素，什么都不会发生，不值得为此付这个代价
- **SQL 识别是结构检查、不是语法校验**（见 `SQLDetector`）：首关键字是 SQL 动词 +
  必配子句整词出现 + 括号引号配平（引号感知）。三条缺一不可 ——
  只看首关键字的话「Update the docs」「select 一下这个方案」全会被误判。
  真做语法校验需要 SQL parser 还得选方言，代价和收益不成比例
- **多语言曾经是死代码：`.lproj` 和 `L()` 都在，但零个调用点。**
  `grep 'L("'` 结果是 0，界面全是硬编码中文，而 docs 里还写着"中英双语"。
  搭好机制却不接上，比没搭更糟 —— 它让人以为这件事做完了。
  加界面时**顺手就要取词**，别攒着以后统一做（攒到 300+ 条就没人愿意动了）。
- **两种语言的词表必须键完全一致**，缺键时 `localizedString(forKey:value:)`
  会把 key 原样显示（界面上冒出 "panel.key.paste"），且不报任何错。
  占位符数量也要一致，少一个是野指针、多一个直接崩。两条都有测试守着
- **架构守卫测试要先剥注释再扫源码**：裸文本匹配会把「这里禁 import SwiftUI」
  这种注释判成违规 —— 一条本来是好事的注释反倒让测试挂掉（真发生过）
- **给 `ClipflowSettings` 加字段会把用户的全部设置清空。** Swift 合成的 `Decodable`
  对缺失的非可选字段抛 `keyNotFound`、**不会**回退到属性默认值，而 `load()` 用 `try?`
  吞掉后返回全默认值 —— 面板尺寸、分栏比例、开发者模式、保留期一起回出厂，还不报错。
  踩过两次（加 `splitRatio`、加 `previewSplitRatio`）。
  已改为手写 `init(from:)` 逐字段 `decodeIfPresent ?? 默认值`，有回归测试
- **互斥的界面状态用一个枚举，别用几个 Bool。** 面板上「分组菜单 / 变换菜单」
  原来是两个 `@Published Bool`，`transformButton` 只把自己置真、忘了清另一个 ——
  点完分组再点变换，两个按钮同时高亮。改成 `enum Popup { none, groups, transforms }`
  之后从根上不可能同时为真，也不用在每个入口手写"顺手关掉另一个"
- **高频操作的选中态不要加过渡动画。** 任何 transition 都意味着"点下去要等它演完"。
  分类切换是高频动作，即时比好看重要
- **"感觉卡"要先量再改，别猜。** `CLIPFLOW_PERF=1` 会把 reload 各阶段耗时
  和"上屏耗时"（CATransaction 完成回调）打到 stderr。这次就是靠它证明
  数据层只占 1~4ms、问题全在视图层的。
  ⚠️ 探针走 **stderr** —— App 的 stdout 重定向到文件后是全缓冲，日志会全丢
- 固定几个提示的底栏**必须能随列宽降级**（`ViewThatFits` 逐级砍掉整条提示，
  配 `fixedSize` 禁止提示内部折行）。不然列一拖窄就把「粘贴」压成两行，整条 footer 变形

### 5.4.1 功能藏得太深 = 等于没做

用户原话："这个 json 格式转换这些我看到并没有实现呢？" —— 实际上 12 个变换全都写好了、
有测试、也能跑。问题是 JSON 那几个标了 `developerOnly`，而开发者模式默认关，
于是 `availableTransforms` 恒为空，连 footer 的 `⌘T 变换` 提示都被 `if !isEmpty` 隐掉了。
**没有任何入口能让人发现它存在。**

判据：一个动作如果只能靠快捷键触发、而快捷键提示本身又是条件显示的，那它对用户不存在。
修法是双管齐下 —— ① 自带内容判定的安全变换（JSON 格式化/压缩，`canApply` 要求真是合法 JSON）
不再归开关管；② 预览头部给常驻可见的按钮（`{} 格式化`、`变换 ⌘T`），
开关只保留"默认就格式化展示"和转义/URL/Base64 这些会污染普通文本的项。

### 5.5 数据正确性

- 去重只更新 `lastUsedAt` 但列表按 `createdAt` 排 → 重新复制的老内容不置顶
- 删条目只删数据库行，**CAS 附件不会跟着删**，磁盘只涨不降 → 需要 `vacuumBlobs()`
- OCR 会把截图里的密码变成**明文可搜索字符串**，绕过整个敏感内容策略 → 敏感结果只存不索引
- **自己写剪贴板后的抑制范围必须精确到一个 changeCount**。旧实现是
  `for d in 0...2 { insert(c + d) }`（注释写"宽容记录附近几个值"），而 `c` 已经是写入
  **之后**读到的计数、就是自己那次；`c+1`/`c+2` 是**用户接下来的两次复制** ——
  于是从面板粘贴一次之后，用户再复制两次全被静默吞掉，永远进不了历史。
  实测复现：粘贴后连续复制 A/B/C/D，只有 C、D 入库。
  修法：抑制值取自写入路径本身（`writeToPasteboard` 返回 changeCount），不事后再读一次；
  `hasChanged()` 只比对最新值、从不枚举中间值，所以精确抑制是安全的。
  回归测试在 `ClipflowCaptureTests`
- **面板里对文本的修改永不写回数据库**。库里存的必须永远是复制那一刻的原样，
  编辑只作用于"这一次复制/粘贴"，切换选中项即丢弃。
  另外**截断的内容禁止编辑** —— 在只显示前 20k 的视图上改完再粘出去，后面那截就没了
- **换掉一个字段时，挂在它身上的保护规则必须跟着搬**。「置顶」被自定义分组取代时，
  `pinned = 0` 这个条件同时出现在敏感 TTL、保留期、条目数上限、清空全部四处 ——
  漏掉任何一处，用户明确归过类的东西就会被自动清理悄悄删掉。
  迁移里也要把已置顶的条目搬进一个叫「置顶」的分组，**功能和数据都不能丢**
- **起名后必须重建 FTS 行**。contentless FTS 不支持 UPDATE，只能先 DELETE 再 INSERT；
  只改 items 表的话用户搜自己起的名字什么也搜不出来，会以为命名功能没做
- 类型分类里 **JSON 判定必须排在 richText 前面**：从网页选中 JSON 复制时剪贴板上
  同时有 html/rtf，先判 richText 这条就成了"富文本"。新增枚举后老数据要回填
  （`reclassifyJSON`，SQL 按"前 3 个字符里有 `{`/`[`"粗筛再逐条真解析，
  绝不能全量解析每条内容）

## 7. 竞品实测结论（对着实际软件核过，非营销页）

| | Paste | Maccy |
|---|---|---|
| 存储 | Core Data，`db.sqlite` 明文 **644**；外置阈值 **128 KiB**；条目为 1 字节前缀 + zlib + JSON（`{types, dataByType}`） | SwiftData，blob 直接内联 SQLite |
| 索引 | 独立 `index.sqlite`：FTS5 external-content + spellfix1 + `items_ocr` / `ocr_queue` | **无索引**，内存线性扫描 + Fuse 模糊匹配，5000 字截断 |
| 文件 | 只存 `public.file-url` 路径引用，**不存文件本体** | 同上 |
| 图片 | **原始 TIFF 不转码** —— 506 个附件里 49 个含 TIFF 却吃掉 346MB（总量 708MB 的 49%） | 内联 |
| 其它 | PostHog 遥测（无会话录制）、本地 MCP server（OAuth2+DCR，端口 39725）、checksum 去重、截图 OCR | 46 语言、Sparkle、App Store |
